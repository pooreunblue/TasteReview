# ADR 리뷰 체크리스트

위쪽 항목이 깨져 있으면 아래를 따져도 의미가 없으므로 순서대로 본다.

## 1. 이 결정이 ADR 감인가
- 되돌리는 데 비용이 큰 선택인가, 아니면 쉽게 바꿀 수 있는 구현 세부인가
- 프레임워크나 상위 제약이 이미 정해 놓은 것을 결정처럼 적고 있지 않은가
- 한 문서에 결정이 하나만 들어 있는가. 둘 이상이면 일부만 대체할 수 없어 나중에 묶여 버린다

## 2. 맥락과 동인
- 맥락 절이 문제를 설명하는가, 아니면 이미 결론을 전제하고 있는가
- 결정 동인이 관련 PRD·SRS 요구사항 ID나 명확한 제약으로 뒷받침되는가
- 시간·비용·역량 같은 비기술적 동인이 있었다면 솔직하게 적혀 있는가

## 3. 대안 비교
- 대안이 둘 이상이고, 각각 실제로 검토할 만한 후보인가
- 모든 대안을 같은 기준으로 비교했는가. 채택안에만 유리한 잣대가 쓰이지 않았는가
- 버려진 대안의 단점이 사실인가, 아니면 결론에 맞춰 과장되었는가
- 각 대안이 다시 유력해지는 조건이 적혀 있는가

## 4. 결정과 결과
- 결정이 한 문장 단정형으로 쓰여 있는가
- 받아들이는 대가가 적혀 있는가. 대가가 없다고 적힌 ADR은 검토가 부족한 것이다
- 후속 작업이 구체적인가 (설정 추가, 문서 갱신, 검증 항목)
- 재검토 신호가 관찰 가능한 조건인가

## 5. 상태와 추적
- 상태값이 실제와 맞는가 (`Proposed`인데 이미 구현되어 있지 않은가)
- 대체된 결정에 `Superseded by NNNN`이 표시되고 양쪽에 상호 링크가 있는가
- `Accepted` 이후 결정 내용이 조용히 고쳐 쓰이지 않았는가. 변경 이력으로 확인한다
- 관련 PRD·SRS가 이 결정과 모순되지 않는가. 모순이 있으면 어느 쪽을 고칠지 사용자에게 알린다
