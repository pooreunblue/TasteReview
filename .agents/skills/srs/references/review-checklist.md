# SRS 리뷰 체크리스트

위쪽 항목이 깨져 있으면 아래 항목을 따져도 의미가 없으므로 순서대로 본다.

## 1. 범위와 추적성
- 선행 PRD가 명시되어 있고, PRD의 목표 범위를 벗어난 요구사항이 들어와 있지 않은가
- PRD의 비목표가 슬그머니 요구사항으로 되살아나지 않았는가
- 추적 매트릭스에서 짝이 없는 PRD 요구사항(누락)이나 출처 없는 SRS 요구사항(범위 이탈)이 있는가

## 2. 요구사항 문장
- 하나의 요구사항이 하나의 진술만 담고 있는가. "그리고"로 이어진 복합 요구사항은 부분 충족 시 판정이 불가능하다
- "적절히", "빠르게", "사용자 친화적으로"처럼 판정 불가능한 표현이 남아 있지 않은가
- 시스템이 해야 할 동작을 기술하는가, 아니면 구현 방법(클래스, 라이브러리, 알고리즘)을 지시하고 있는가
- 각 요구사항에 고유 ID가 있고 본문 다른 곳에서 그 ID로 참조되는가

## 3. 예외와 경계
- 기능마다 입력 검증 실패, 권한 없음, 대상 없음이 정의되어 있는가
- 중복 제출, 동시 수정, 재시도 같은 반복 요청 상황이 다뤄졌는가
- 상한·하한(길이, 개수, 용량, 페이지 크기)이 숫자로 정해져 있는가
- 삭제·변경 시 연관 데이터의 처리가 명시되어 있는가

## 4. 인터페이스 계약
- 화면 경로와 요청 방식, 입력 필드와 제약, 성공 후 이동 위치가 모두 적혀 있는가
- 서버 렌더링 전제에서 상태 변경이 POST 후 리다이렉트로 관찰되도록 기술되어 있는가
- 외부 자원(파일 시스템, DB, 외부 API) 실패 시 시스템 동작이 정의되어 있는가

## 5. 품질 속성
- 성능·보안·호환성 요구사항에 측정 조건과 수치가 있는가
- 측정 지점이 명확한가. 어디서 재는지 없는 응답 시간 수치는 검증할 수 없다
- 보안 요구사항이 관찰 가능한 형태인가 (예: 토큰 없는 요청 거부, 로그에 비밀번호 미기록)

## 6. 가정과 미해결 이슈
- 가정이 단정형 요구사항으로 위장되어 있지 않은가
- 각 가정에 대해 틀렸을 때 영향받는 요구사항이 적혀 있는가
- 미해결 이슈가 질문 형태로 남아 있고, 결정된 항목은 본문으로 옮겨졌는가
- 변경 이력과 프런트매터 상태·수정일이 실제 내용과 일치하는가
