# 디자인 리뷰 체크리스트

`DESIGN.md`의 규칙을 기준으로 아래 순서로 본다. 위쪽이 사용자에게 먼저 드러나는 문제다.

## 1. 모바일
- 폭 360px에서 가로 스크롤이 생기지 않는가. 긴 가게명, 넓은 표, 고정 폭 이미지가 흔한 원인이다
- 터치 대상이 44×44px 이상인가. 페이지 번호와 아이콘 버튼이 가장 자주 어긴다
- 입력 요소 글자 크기가 16px 이상인가. 미만이면 iOS에서 포커스 시 화면이 확대된다
- 브레이크포인트가 600px·960px 두 개만 쓰이는가
- 이미지에 `aspect-ratio`가 지정되어 로딩 중 레이아웃이 밀리지 않는가

## 2. 색
- 사용된 색이 모두 토큰인가. CSS 규칙 본문에 직접 적힌 색 값이 있는가
- 중립 회색(`#888`, `#ccc` 등)이 섞여 들어와 따뜻한 기조를 깨뜨리지 않았는가
- 본문 텍스트 대비 4.5:1, 아이콘·테두리 3:1을 만족하는가
- 다크 모드에서 같은 토큰이 재정의되어 있고 대비가 유지되는가
- 상태(오류·성공·별점)를 색만으로 전달하지 않는가. 문장이나 숫자가 함께 있는가

## 3. 서체
- Pretendard 외 서체가 섞이지 않았는가
- 스타일시트 버전이 고정되어 있는가. 최신 태그를 참조하면 어느 날 갑자기 자형이 바뀐다
- 서체 로드에 실패해도 대체 스택으로 읽히는가
- 크기가 타이포그래피 표의 5단계 안에 있는가. 임의 크기가 늘면 위계가 사라진다

## 4. 여백
- 패딩·마진·간격이 모두 8의 배수인가. 1px 테두리와 2px 포커스 링만 예외다
- 같은 역할의 간격이 화면마다 다른 값을 쓰지 않는가
- 카드 내부 16px, 항목 사이 24px, 섹션 사이 32px 같은 기본 조합에서 벗어난 이유가 있는가

## 5. 구조와 접근성
- 스타일이 단일 CSS 파일에 있고 템플릿에 인라인 `style`이 없는가
- 클래스 이름이 `블록__요소` 형태를 따르는가
- 스타일이나 상호작용을 위해 JavaScript에 의존하지 않는가(서버 렌더링 전제)
- `:focus-visible` 외곽선이 살아 있는가
- 이미지에 의미 있는 `alt`가 있는가. 장식 이미지는 빈 `alt`인가
