# PRD 리뷰 체크리스트

PRD를 리뷰할 때 아래 순서로 본다. 위쪽 항목이 깨져 있으면 아래 항목은 대부분 의미가 없으므로 먼저 지적한다.

## 1. 문제 정의
- 배경 절이 해결책이 아니라 문제를 설명하고 있는가
- 이 기능을 만들지 않으면 생기는 손해가 드러나는가
- 문제를 겪는 사용자가 구체적으로 지목되어 있는가

## 2. 범위
- 비목표가 비어 있거나 형식적이지 않은가 (빈 비목표는 범위가 통제되지 않는다는 신호다)
- 목표와 요구사항이 서로 대응하는가, 목표에 없는 요구사항이 몰래 들어와 있지 않은가
- 1단계 범위만으로도 사용자에게 가치가 전달되는가

## 3. 요구사항의 검증 가능성
- 각 요구사항이 참/거짓을 판정할 수 있는 문장인가
- "빠르게", "편리하게", "적절히" 같은 판정 불가능한 표현이 남아 있지 않은가
- 비기능 요구사항에 수치나 조건이 붙어 있는가
- ID(FR-n, NFR-n)가 붙어 있어 이후 논의에서 참조 가능한가

## 4. 예외와 경계
- 입력 검증 실패, 권한 없음, 데이터 없음 같은 비정상 흐름이 다뤄졌는가
- 동시 수정, 중복 등록처럼 경합이 생기는 지점이 고려되었는가
- 삭제나 수정 시 연관 데이터를 어떻게 할지 정해져 있는가

## 5. 구현 가능성 (Java 17 / Spring Boot / Thymeleaf 기준)
- 서버 렌더링 전제와 맞지 않는 화면 동작을 요구하고 있지 않은가
- 컨트롤러·서비스·도메인 계층 분리를 깨야만 만들 수 있는 요구사항이 있는가
- 기존 도메인 모델과 충돌하거나 중복되는 개념을 새로 만들고 있지 않은가

## 6. 측정과 후속
- 성공 지표가 실제로 수집 가능한 값인가
- 미해결 질문이 질문 형태로 남아 있고, 답이 나온 것은 본문으로 옮겨졌는가
- 변경 이력과 프런트매터의 상태·수정일이 실제 내용과 일치하는가
