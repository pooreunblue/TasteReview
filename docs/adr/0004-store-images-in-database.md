# 0004. 리뷰 사진을 데이터베이스에 저장한다

## 1. 맥락과 문제

리뷰에는 사진을 최대 5장 첨부할 수 있다(SRS-F-15). PRD 초안은 사진을 서버 로컬 파일시스템에 저장한다고 적었다(당시 FR-9).
그런데 Render 무료 인스턴스의 파일시스템은 휘발성이어서 재배포나 재시작 때마다 업로드된 사진이 전부 사라진다. 초안대로 두면 등록된 리뷰의 사진이 통째로 없어지는 결함이 배포 첫날 발생한다. 사진 바이너리를 어디에 둘지 다시 정해야 한다.

## 2. 결정 동인

- (제약) 애플리케이션 인스턴스의 로컬 파일시스템은 휘발성이다(0002의 결과, SRS 5절 C-4).
- (제약) 구현에 허용된 시간이 약 1시간이다. 새 외부 서비스 계정·버킷·자격 증명을 추가할 여유가 적다.
- (요구사항) 컨테이너 재시작 후에도 기존 사진이 모두 조회되어야 한다(SRS-Q-10).
- (비용) 무료 플랜 범위에서 운영한다. Neon 무료 플랜의 저장 용량은 제한적이다.
- (요구사항) 목록·검색 조회가 사진 바이너리 때문에 느려지지 않아야 한다(SRS-Q-1).

## 3. 검토한 대안

### 대안 A. PostgreSQL에 바이너리로 저장
사진을 데이터베이스 컬럼에 담고 별도 경로로 서빙한다.
- 장점: 추가 인프라와 자격 증명이 필요 없어 1시간 제약에 맞는다. 리뷰와 사진의 트랜잭션 일관성이 자연히 보장되어 리뷰 삭제 시 사진이 함께 사라진다(SRS-F-12). 재배포에도 유실되지 않는다.
- 단점: 데이터베이스 용량을 빠르게 소모한다. 백업 크기가 커진다. CDN 캐싱 이점을 얻을 수 없다. 조회 시 바이너리를 함께 읽지 않도록 주의해야 한다.
- 다시 유력해지는 조건: 해당 없음(현 채택안, 단 임시 구조로 본다).

### 대안 B. 외부 오브젝트 스토리지(S3, Cloudflare R2)
사진은 스토리지에, 메타데이터만 데이터베이스에 둔다.
- 장점: 용량과 비용 측면에서 정석이다. CDN과 결합하기 쉽고 데이터베이스 부담이 없다.
- 단점: 계정·버킷·자격 증명 발급과 SDK 연동, 업로드 실패 시 정합성 처리가 더해져 1시간 안에 완료하기 어렵다. 리뷰 삭제와 파일 삭제가 별개 트랜잭션이 되어 고아 파일 처리가 필요하다.
- 다시 유력해지는 조건: 데이터베이스 용량이 한도에 근접할 때, 또는 이미지 전송량이 늘어 캐싱이 필요할 때. 이 결정을 대체할 가장 유력한 후보다.

### 대안 C. Render 영구 디스크 부착
인스턴스에 영구 볼륨을 붙여 로컬 저장을 유지한다.
- 장점: PRD 초안의 구현 방식을 그대로 쓸 수 있다.
- 단점: 유료 기능이라 무료 운영 전제와 충돌한다. 디스크를 붙이면 인스턴스를 여러 대로 늘릴 수 없어 확장 경로가 막힌다.
- 다시 유력해지는 조건: 유료 전환이 확정되고 단일 인스턴스 운영을 계속 유지할 때.

## 4. 결정

**우리는 리뷰 사진 바이너리를 PostgreSQL에 저장하고, 애플리케이션 로컬 파일시스템에는 영구 보관하지 않는다.**

가장 무겁게 본 동인은 1시간 제약과 무료 운영이다. 정석인 오브젝트 스토리지는 이번 시간 예산 안에서 연동·정합성 처리까지 끝내기 어렵다.
이 결정은 영구적인 구조가 아니라 외부 스토리지로 전환하기 전까지의 임시 구조로 본다.

## 5. 결과

- **얻는 것**: 추가 인프라 없이 사진 유실 문제가 해소된다. 리뷰와 사진이 한 트랜잭션에서 정리된다.
- **받아들이는 대가**: 장당 5MB × 리뷰 200건 수준이면 Neon 무료 용량 한도에 접근한다. 이미지 전송이 애플리케이션과 데이터베이스를 모두 거친다. 백업 크기가 커진다.
- **후속 작업**: 장당·요청당 크기 상한을 설정으로 통제한다(SRS-F-17, 0006). 목록·검색 조회에서 바이너리를 함께 읽지 않도록 한다(SRS 8절). 용량 점검 절차를 마련한다(SRS-Q-13).
- **재검토 신호**: 데이터베이스 사용량이 무료 한도의 70%를 넘을 때, 또는 이미지 응답이 성능 기준을 위협할 때. 이때 대안 B로 전환하고 이 ADR을 대체한다.

## 6. 준수 확인 방법

업로드 경로가 로컬 디스크에 파일을 영구 기록하지 않는지 검사한다(SRS-F-18).
재배포 후 기존 리뷰의 사진이 그대로 보이는지 확인한다(SRS-Q-10).
